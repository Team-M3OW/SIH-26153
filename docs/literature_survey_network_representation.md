# Literature Survey: Network State Representation for World-Model-Based Predictive Cyber Defence

Scope: this survey targets requirement #1 of SIH26153 — "represent network state as a structured feature vector or graph encoding active flows at time t" — as the foundation for a sequence/GNN model learning `P(S_t+1 | S_t)` and forecasting MITRE ATT&CK stage progression. It is organized around the six sub-areas relevant to that design decision, closing with a concrete recommendation for our system.

---

## 1. Flow-level feature-vector representations for NIDS

The dominant representation in production and academic NIDS is the **flow record**: a fixed-length feature vector summarizing one bidirectional (or unidirectional) TCP/UDP/ICMP conversation between two endpoints over its lifetime.

- **Sharafaldin, Lashkari & Ghorbani, "Toward Generating a New Intrusion Detection Dataset and Intrusion Traffic Characterization" (ICISSP 2018)** — the CICIDS2017/CIC-IDS-2018 paper. Introduces **CICFlowMeter**, which derives ~80 features per flow from raw PCAP: duration, packets/bytes forward and backward, inter-arrival-time (IAT) mean/std/min/max (both directions), flag counts (SYN/ACK/FIN/RST/PSH/URG), packet-length statistics, subflow stats, active/idle time. This feature set — and its labeling methodology (attack timeline windows per day) — is exactly what CIC-IDS-2018 supplies and is the natural starting point for our flow-level features.

- **Sarhan, Layeghy, Moustafa & Portmann, "NetFlow Datasets for Machine Learning-Based NIDS" (arXiv 2020, 333 citations)** and **"Towards a Standard Feature Set for NIDS Datasets" (Mobile Networks & Applications, 2021, 393 citations)** — re-derive UNSW-NB15, BoT-IoT, ToN-IoT and CSE-CIC-IDS2018 into a common **NetFlow v9/IPFIX-style feature set** (12- and 43-feature variants), because the proprietary per-dataset feature sets make cross-dataset comparison and generalization claims meaningless. Key finding: a *smaller, standardized* feature set generalizes better across environments than an over-engineered dataset-specific one, and it maps 1:1 onto what a real NetFlow/IPFIX exporter emits in production — directly relevant to "enterprise applicability."

- **Sarhan et al., "Evaluating Standard Feature Sets Towards Increased Generalisability and Explainability of ML-Based NIDS" (Big Data Research, 2021, 133 citations)** — evaluates NetFlow vs. CICFlowMeter feature sets across CSE-CIC-IDS2018, BoT-IoT, ToN-IoT and uses **SHAP** to show NetFlow's smaller feature set is both more generalizable *and* more explainable (fewer, more meaningful Shapley-weighted features).

- **Kılıç et al., "SHAP-Guided Feature Selection for Cross-Dataset Generalization in NIDS" (IEEE Access, 2026)** — trains Random Forest/XGBoost on CICIDS2017's 80-dim CICFlowMeter space, tests on CSE-CIC-IDS2018: macro-F1 collapses from ~0.90 to 0.12–0.13 despite near-perfect same-dataset accuracy. This is a **direct warning against the failure mode the PS explicitly penalizes** ("generalize to unseen attack patterns, not merely memorize signatures") — a model that looks excellent on a CIC-IDS-2018 train/test split can still be badly overfit to that dataset's idiosyncrasies (e.g., source/destination IP acting as a leaking proxy label, since only a few attacker IPs are used).

- **Göcs et al., "Identifying Relevant Features of CSE-CIC-IDS2018" (Intelligent Data Analysis, 2023)** and **Maabreh et al. (2022)** — feature-selection studies specifically on CSE-CIC-IDS2018, both finding that only a handful of features (forward-direction and flow-level aggregate stats) carry most of the discriminative signal, and that dropping port/IP identity features barely hurts and measurably helps generalization (confirms Kılıç et al.'s point about identity leakage).

**Synthesis.** The flow-vector tradition is mature, well-benchmarked, and directly consumable from CIC-IDS-2018 CSVs. Its known failure mode is exactly the one the PS wants us to avoid: near-perfect same-dataset numbers driven by dataset artifacts (source IP, absolute timestamps, dataset-specific port conventions) rather than genuine attack-behavior signal. **Actionable implication:** drop raw IP/port identity from the model's input features (keep them as metadata for the explainability/UI layer only), and evaluate on a held-out *day* or *attack family* from CIC-IDS-2018 rather than a random row split, or the "generalizes to unseen attacks" claim in our benchmark section will not hold up.

## 2. Graph-based network representations

Flow vectors treat each flow independently; a graph representation makes the *relational* structure — which hosts talk to which, how many flows, fanning in/out — a first-class part of the state, which is what actually surfaces coordinated behavior (port scans, botnet C2 fan-out, lateral movement) that per-flow statistics miss.

The field splits into two representation families:

### 2a. Flow/host graphs (nodes = IPs, edges = flows) — the NIDS-native design

- **Lo, Layeghy, Sarhan, Gallagher & Portmann, "E-GraphSAGE: A GNN-Based IDS for IoT" (NOMS 2022, arXiv:2103.16329)** — the foundational design for this family. **Nodes = IP:port endpoints** (feature-less; initialized to an all-ones vector), **edges = individual flows**, carrying the flow's NetFlow features (bytes, packets, duration, flags, etc.) as *edge* features. Extends GraphSAGE's node-only message passing to aggregate **edge features** during neighborhood aggregation (Eq. 4: `h^k_N(v) = AGG({e_uv^(k-1) : u ∈ N(v)})`), then classifies **edges** (flows) rather than nodes — because in NIDS the label lives on the flow, not the host. Inductive (GraphSAGE-style sampling), so it generalizes to IPs unseen at training time — unlike earlier transductive graph-embedding NIDS approaches (Xiao et al. 2020). Randomizes source-IP mapping specifically to prevent the model from leaking attacker identity through node identity — the same failure mode flagged in §1. Outperforms SOTA classifiers on 4 IoT NIDS benchmarks (BoT-IoT, ToN-IoT and NetFlow variants).

- **Caville, Lo, Layeghy & Portmann, "Anomal-E: A Self-Supervised NIDS based on GNNs" (Knowledge-Based Systems, 2022, arXiv:2207.06819)** — same E-GraphSAGE graph construction, but trains the encoder **self-supervised** via **Deep Graph Infomax (DGI)**: maximize mutual information between local edge embeddings and a global graph summary vector, using a corrupted (permuted) graph as the negative sample. This means benign-only training is sufficient to get useful edge embeddings, then a lightweight classifier (Isolation Forest, PCA, CBLOF, HBOS) sits on top — valuable because labeled multi-stage-attack ground truth is scarce, and matches the PS's "generalize beyond memorized signatures" requirement better than fully-supervised flow classifiers.

- **Kaya, Ak, Bas, Canberk & Oguducu, "X-CBA: Explainability Aided CatBoosted Anomal-E" (IEEE ICC 2024, arXiv:2402.00839)** — same E-GraphSAGE + DGI edge embeddings, replaces the downstream classifier with **CatBoost** (98.7% F1-macro on NF-CSE-CIC-IDS2018-v2, beating Anomal-E's best variant at 94.4%) and adds **PGExplainer** for edge-level explainability (see §6). Directly relevant as a template: *self-supervised graph encoder → gradient-boosted classifier → graph-native explainer*, which is a strong, already-benchmarked pattern for the flow-graph half of our design.

- **Xiao et al. (cited in E-GraphSAGE's related work)** — earlier first/second-order IP:port graph embeddings, transductive (fails on unseen IPs) — useful as the "what not to do" baseline.

### 2b. Provenance / process graphs (nodes = system entities) — the APT/host-telemetry family

- **CONTINUUM (Bahar et al. 2025, arXiv:2501.02981)** — nodes = system entities (files, processes, sockets), edges = system-call-level interactions (read/write/execute), aggregated into per-window **snapshots**. Uses a **Spatio-Temporal GNN autoencoder**: Graph Attention Network (GAT) layers for spatial structure (with edge features folded into the attention mechanism, following MAGIC), **GRU** layers for temporal evolution across snapshots, trained as an autoencoder on benign data only, with **K-NN on the resulting embeddings** for anomaly scoring. Adds a federated-learning + homomorphic-encryption deployment layer (privacy across organizations) — not core to the PS but shows the architecture scales to a federated enterprise setting. Near-perfect scores on DARPA E3 provenance datasets.

- **Phan & Bauschert, "Learning the APT Kill Chain: StageFinder" (arXiv:2603.07560)** — the single most directly relevant paper found for our exact task. Builds a **fused host+network provenance graph** per time window: nodes = processes/files/sockets/users **plus IDS/firewall alert nodes** (a novel move — network-layer alerts become first-class graph nodes linked to the host entities that triggered them, via `triggered_by`/`connect` edges), giving "causal completeness" across the host/network boundary. A multi-relational GNN encoder (message passing per edge-type: read/write/spawn/connect/triggered_by) produces one graph embedding `g_t` per window; a stacked **LSTM** consumes the sequence `{g_1,...,g_t}` and a softmax head outputs a probability distribution over **6 explicit MITRE ATT&CK stages** (Recon → Initial Compromise → Privilege Escalation → Lateral Movement → C2 → Exfiltration) plus benign. Pretrained self-supervised (next-embedding prediction + temporal contrastive loss) on unlabeled DARPA OpTC, fine-tuned supervised on labeled DARPA TC. Reports macro-F1 0.96 and a 31% reduction in prediction "flip rate" (temporal instability) vs. two baselines. This paper is essentially a worked example of exactly the GNN-encoder → LSTM-temporal-head → ATT&CK-stage-output pipeline the PS describes, just built on host provenance logs rather than pure network flows — the adaptation needed for us is swapping provenance nodes/edges for flow-graph nodes/edges (§2a) while keeping the GNN→LSTM→stage-softmax skeleton.

**Synthesis — the key design fork.** Provenance graphs (2b) give the cleanest, most literal mapping onto MITRE ATT&CK tactics because they capture host-level causality (process spawns, file writes) that directly corresponds to ATT&CK techniques — but they require host-agent/EDR-style telemetry (Sysmon, DARPA TC/OpTC-style logs), which the PS's mandated datasets (CIC-IDS-2018, CTU-13) do **not** provide; those are purely network-vantage-point captures. Flow graphs (2a) are the only option that is actually constructible from NetFlow/PCAP alone, which is what the PS's expected datasets and packet-level requirement give us. **This determines our answer in the Recommendation section below: we must use the flow-graph family (2a), and borrow the temporal-encoder-over-graph-embeddings pattern from StageFinder (2b) rather than its graph construction.**

## 3. Sequential / temporal state representations (windowed flow features, no graph)

Before or alongside graphs, several works apply LSTM/GRU/Transformer directly to **sequences of windowed flow-aggregate feature vectors** — i.e., treating network state at time *t* as a plain vector (not a graph) and letting a sequence model carry the temporal context.

- **Zhang, Chen et al., "Network Intrusion Detection: Based on Deep Hierarchical Network and Original Flow Data" (IEEE Access, 2019, 163 citations)** — combines a CNN (LeNet-5-style, over raw per-packet bytes) with an **LSTM** over the resulting sequence, evaluated on CICIDS2017 *and* the CTU-13 dataset (same two dataset families named in our PS). Confirms the "spatial-then-temporal" cascade (per-window feature extraction → sequence model) is a viable, previously-validated recipe on exactly the datasets we're using.

- **Bontemps et al. (2016)** and **Vinayakumar et al. (2019)** — foundational LSTM-for-NIDS papers (cited as baselines by both PARD-SSM and StageFinder above): stacked LSTM/BiLSTM over per-flow or per-window feature sequences for anomaly/attack classification. These are the "reactive black-box sequence model" baseline that both PARD-SSM and StageFinder explicitly position themselves against — worth replicating as *our* baseline-plus-one (a plain BiLSTM over flow-feature windows, no graph, no explicit regime/stage structure), since it isolates exactly how much the graph and/or explicit-stage-structure choices are contributing.

- **Wu et al., "NetTrans" (IEEE GLOBECOM 2021)** — applies Transformer self-attention directly to flow-level sequences for traffic classification, cited as a modern non-graph sequence baseline.

**Synthesis.** Pure sequential-over-feature-vector approaches are simpler to implement and train than graph+sequence hybrids, and are a legitimate architecture choice per the PS ("LSTM, Temporal Transformer, or GNN" are offered as alternatives, not requirements to combine). Their limitation, repeatedly noted by both the graph papers and PARD-SSM, is that they discard the *relational* signal (fan-out to many destinations, coordinated multi-host scanning) that is often the strongest tell for reconnaissance and lateral movement specifically — the two ATT&CK stages the PS calls out. **This is why the strongest recent papers (StageFinder, CONTINUUM) combine a graph encoder per window with a sequence model across windows, rather than picking one or the other.**

## 4. World models and latent state-space models

This is the area the PS explicitly frames as its conceptual anchor, but — as expected — there is essentially **no published work applying the Ha & Schmidhuber / Dreamer lineage of world models directly to network security**. The relevant literature splits into (a) the general world-model lineage, and (b) probabilistic latent state-space models that have actually been applied to network/cyber telemetry and are functionally the same idea under a different name.

### 4a. The general world-model lineage (RL / control, not security)
- **Ha & Schmidhuber, "World Models" (2018)** — VAE (compresses observation → latent `z`) + RNN/MDN-RNN (predicts `P(z_{t+1} | z_t, a_t)`) + a small controller trained inside the learned "dream." Establishes the VAE+RNN latent-dynamics-model template that everything below inherits.
- **Hafner et al., PlaNet (2019)** — introduces the **Recurrent State-Space Model (RSSM)**: a latent state with both a deterministic (RNN) component and a stochastic (Gaussian) component per step, trained to predict multi-step future latents/observations/rewards. This deterministic+stochastic split is architecturally the closest general-ML analogue to PARD-SSM's regime+continuous-state split below.
- **Dreamer / DreamerV2 / DreamerV3 (Hafner et al., 2020–2023)** — train an actor-critic entirely inside RSSM-imagined rollouts; DreamerV3 in particular is notable for being a *single, robust configuration* across 150+ heterogeneous tasks without per-task tuning, via return/KL normalization — relevant to us mainly as evidence that **latent state-space models trained purely on predicting future observations, without any bespoke security priors, do scale and generalize** across very different "environments," a reassuring precedent for asking a network-traffic latent model to generalize across attack types.
- Adjacent 2025–2026 arXiv work (Looped World Models, Mamba-based SSMs for anomaly detection, KAN-Dreamer, etc.) confirms this is a very active general area, but confirms none of it has a network-security instantiation yet — **this is a genuine, citable gap**, and framing our submission explicitly as "the first application of the RSSM-style stochastic+deterministic latent transition model to network-flow-graph state" is a legitimate, defensible novelty claim for the hackathon.

### 4b. Latent/probabilistic state-space models actually applied to cyber telemetry
- **PARD-SSM, "Probabilistic Cyber-Attack Regime Detection via Variational Switching State-Space Models" (2026, arXiv:2604.02299)** — the closest thing to a "world model for network security" in the literature, despite not using that name. Models network telemetry as a **Regime-Dependent Switching Linear Dynamical System**: a discrete regime variable `s_t ∈ {Normal, Recon, Lateral-Movement/Intrusion, Exfiltration}` (i.e., **coarse-grained MITRE-ish kill-chain stages baked directly into the generative model**) gates which of 4 regime-specific linear dynamics `x_t = A^(s)x_{t-1} + w_t` governs an 8-dim continuous latent "network health" state, which in turn emits a 17-dim observation vector (IAT stats, port entropy, SYN/ACK ratio, payload entropy, fragment rate, DNS/ICMP rates, etc. — a compact, well-chosen flow+packet-level feature vector, worth mirroring). Inference is a **structured mean-field variational approximation** (regime-weighted Kalman smoother + HMM forward-backward), making it tractable at <1.2ms/flow on CPU with *no GPU*. Critically, this is the only system in the entire survey that demonstrates genuine **predictive** kill-chain forecasting: by exploiting the learned off-diagonal transition-matrix structure (`Π_recon→intrusion = 0.15`, `Π_intrusion→exfil = 0.25`, near-zero reverse transitions), it issues alerts ~8 minutes *before* ground-truth attack onset on CICIDS2017 — the exact "roll out K steps, forecast infiltration before completion" capability the PS asks for, achieved via `γ̂_{t+τ} = (Π^τ)ᵀγ_t`, i.e. literally forward-simulating the learned transition dynamics. Reports F1 0.982 (CICIDS2017) vs. 0.744 for a BiLSTM baseline and 0.680 for a single-regime Kalman filter (proving the *switching/regime* structure, not just "some temporal model," is what buys the gain) — this is a strong existence proof that explicit regime-structured dynamics beat both naive sequence models and non-switching state-space models on the *predictive* part of the task specifically.
- **General anomaly-detection latent state-space models** (OmniAnomaly-style LSTM-VAE, Latent SDEs for sparse/irregular multivariate time series, arXiv:2606.18898) — same "compress to latent, model latent dynamics, reconstruct/predict" recipe as Ha & Schmidhuber, applied to multivariate telemetry in general (not network-specific) — useful mainly as evidence that variational latent-dynamics models are a mature, tractable technique for the kind of high-dimensional, noisy sensor-like data flow telemetry resembles.

**Synthesis.** There is a real, citable gap between "world models" as a term of art (control/RL, image-based, no cyber application) and what the cybersecurity literature has actually built (PARD-SSM's switching SSM, StageFinder's GNN+LSTM, CONTINUUM's STGNN autoencoder) — all of which *are* world models in the PS's functional sense (`P(S_t+1|S_t)`, forward rollout, stage attribution) without using RSSM/Dreamer machinery. **Actionable implication:** PARD-SSM is the paper to explicitly position against/build on — its discrete-regime + continuous-latent split is directly reusable regardless of whether we choose an LSTM, Transformer, or GNN for the continuous part, and its off-diagonal-transition-matrix rollout is the simplest, most explainable way to satisfy "estimate probability of attacker progression K steps ahead" (much more transparent than a black-box multi-step LSTM decoder, and gradable in a demo since the regime-transition matrix can literally be shown to a judge).

## 5. Multi-stage attack / kill-chain / MITRE ATT&CK mapping

- **Hutchins, Cloppert & Amin (2011)** — the original Lockheed Martin "Cyber Kill Chain," the conceptual ancestor of both ATT&CK and every "stage" abstraction used above.
- **MITRE ATT&CK (Strom et al., 2018)** — the enterprise tactic/technique matrix the PS asks us to map onto; StageFinder (§2b) gives a clean worked 6-stage collapse of it (Recon, Initial Compromise, Privilege Escalation, Lateral Movement, C2, Exfiltration) that is a good match for the PS's own 5-stage list (Recon, Initial Access, Lateral Movement, C2, Exfiltration) — essentially the same taxonomy with Initial Access/Compromise combined and Privilege Escalation folded in or dropped, which is a reasonable simplification for our scope.
- **Ourston et al. (2003) / Li et al. (2013)** — early HMM-based multi-stage-attack modeling; conditional-independence assumptions make them unable to model realistic non-stationary traffic (the exact limitation PARD-SSM's switching-SSM was built to fix).
- **KillChainGraph (2025, arXiv:2508.18230)** — phase-aware multi-model ML framework predicting/mapping ATT&CK techniques from telemetry; relevant as a second data point on stage-classification framing, though the discover_papers abstract suggests a more traditional alert-correlation approach (LLM/CTI-driven attack-chain-reconstruction papers found alongside it — DiagChain, BEACON, CRUcialG, ChainWatch — are largely about mining *threat-intelligence reports*, i.e., text, not network telemetry, so are out of scope for our representation question, but confirm ATT&CK-stage mapping from raw telemetry, specifically, is a less-crowded sub-problem than text-based CTI mapping).
- **Ning, Cui & Reeves (2002); Sheyner et al. (2002)** — classical static attack-graph / alert-correlation approaches; require accurate point alerts from a lower-level IDS as input and cannot do the "predict before completion" forward simulation the PS wants — cited by PARD-SSM as the baseline this whole line of probabilistic work supersedes.

**Synthesis.** No dataset in our candidate pool (CIC-IDS-2018, CTU-13) ships with native MITRE ATT&CK labels — every system above (PARD-SSM's 4 regimes, StageFinder's 6 stages) had to construct its own stage taxonomy and map dataset attack-type labels onto it by hand. **Actionable implication:** we need a small, explicit, documented mapping table (e.g., CIC-IDS-2018's `PortScan`→Reconnaissance, `FTP/SSH-Patator`→Initial Access, `Infiltration`→Lateral Movement, `Bot`→Command & Control, `DDoS/DoS-*`→ either excluded or treated as a separate non-kill-chain "availability attack" class since PS's 5 stages don't include DoS) as a first-class, versioned artifact of the project — this mapping is itself a reviewable/gradable deliverable, not an incidental implementation detail.

## 6. Explainability for graph/sequence security models

- **GNNExplainer (Ying, Bourgeois, You, Zitnik & Leskovec, NeurIPS 2019)** — the original post-hoc GNN explainer: learns a soft mask over edges/node-features per prediction, maximizing mutual information between the masked subgraph and the model's output. Treats the GNN as a black box (no retraining needed), but produces one explanation *per instance*, is a maximization that can get stuck in local optima, and — per X-CBA's benchmark below — underperforms on inductive, flow-graph-style settings.
- **PGExplainer (Luo et al., NeurIPS 2020)**, used in **X-CBA (arXiv:2402.00839, §2a above)** — trains a *shared* explanation network (rather than optimizing per-instance) that predicts edge-importance masks, enabling **global** explanations (patterns across many flows of the same attack type) in addition to local ones, and operates natively in the **inductive** setting flow-graphs require (new IPs/flows at test time). X-CBA's head-to-head benchmark found PGExplainer strictly dominates GNNExplainer on both Sparsity and Fidelity⁺ metrics on NF-CSE-CIC-IDS2018-v2, and — concretely relevant to our "driving features" requirement — PGExplainer correctly isolates the sparse, indirectly-connected flows characteristic of an **Infiltration** attack, where GNNExplainer confuses Infiltration with Bot. This is directly actionable: **if we build a flow-graph GNN, PGExplainer over GNNExplainer is an evidence-backed choice, not a toss-up.**
- **SHAP (Lundberg & Lee, 2017)**, used throughout §1's feature-set papers (Sarhan et al. 2021, Kılıç et al. 2026) — the standard choice when the model is *not* graph-structured (e.g., our flow-vector baseline / non-graph LSTM path, or the logistic-regression baseline the PS explicitly requires us to benchmark against). TreeSHAP is cheap enough to run per-prediction for a gradient-boosted or linear baseline; KernelSHAP/DeepSHAP would be needed for an LSTM, at higher cost.
- **StageFinder's temporal-attention visualization (§2b)** — a lighter-weight explainability channel worth noting: simply plotting the LSTM's attention/hidden-state activity over the time axis and showing it concentrates on the windows immediately preceding a stage transition is a legitimate, cheap "why now" explanation to pair with feature-level attribution, and demos well.
- **PARD-SSM's regime posteriors and KL-gating score (§4b)** — arguably the most *inherently* interpretable option of everything surveyed: because the state is an explicit discrete regime with a human-readable label (Normal/Recon/Lateral-Movement/Exfil) and the model *is* a probabilistic graphical model rather than a black box, "explainability" is close to free — the regime posterior `γ_t(s)` and the learned transition matrix `Π` are both directly interpretable outputs, not a post-hoc approximation of a black box. This is a meaningful architectural trade-off point.

**Synthesis.** For a **graph-based** design, PGExplainer > GNNExplainer is empirically settled by X-CBA on datasets in our own candidate pool. For a **non-graph** design (flow-vector LSTM/Transformer or the required logistic-regression baseline), SHAP is standard and cheap. A hybrid architecture (see Recommendation) can and should use **both**: PGExplainer/attention on the graph-encoder half for "which flows/hosts drove this," SHAP on the final stage-classifier head for "which aggregate features drove this."

## Recommendation

**Design: a two-level hybrid — flow-graph encoder per time window, feeding a regime-structured temporal model.**

1. **State representation, per fixed window (e.g. 1–5s, matching PARD-SSM's `W`):** build an **E-GraphSAGE-style flow graph** (§2a) — nodes = IP:port endpoints (feature-less, all-ones init, exactly as E-GraphSAGE/Anomal-E do, to stay inductive over unseen IPs), edges = individual flows carrying a feature vector that merges **CICFlowMeter/NetFlow flow-level features** (from CIC-IDS-2018 CSVs) *and* **packet-level features** (TTL variance, window size, fragment flags, payload-size distribution, retransmission count, port-scan sequencing — from CTU-13 PCAPs), directly answering the PS's "both levels required" mandate at the edge-feature level rather than bolting packet features on as an afterthought. This also sidesteps the CIC-IDS-2018 identity-leakage failure mode from §1 by construction (E-GraphSAGE already randomizes/drops IP identity as a *feature*, while still using it as a graph *key*).
2. **Per-window graph embedding:** run 2 E-GraphSAGE layers (as in the original paper) to get a graph-level embedding via readout (mean-pool of edge/node embeddings) — optionally pretrained self-supervised via DGI (Anomal-E) if labeled multi-stage sequences turn out to be too sparse in CTU-13.
3. **Temporal dynamics — this is where we take PARD-SSM's core idea over a plain LSTM:** feed the sequence of per-window graph embeddings into a model with an **explicit discrete regime/stage variable** (Normal / Recon / Lateral-Movement / C2 / Exfiltration, adapted to the PS's 5-stage list per §5's mapping table) whose transitions are learned, rather than a plain LSTM with an opaque hidden state. The simplest defensible version for a hackathon timeline: an **LSTM or Transformer head outputting a softmax over the 5 ATT&CK-mapped stages per window** (StageFinder's approach, §2b) *plus* an explicitly materialized, learned stage-transition matrix `Π` (PARD-SSM's approach, §4b) estimated from the sequence of predicted stages — giving us PARD-SSM's K-step forward-rollout capability (`γ̂_{t+K} = (Π^K)ᵀγ_t`) essentially for free on top of a standard sequence classifier, without needing to implement full variational switching-SSM inference under time pressure.
4. **Explainability:** PGExplainer on the graph-encoder half (which flows/hosts drove this window's embedding — evidence-backed as the stronger choice per X-CBA, §6) + attention-weight visualization over the LSTM/Transformer time axis (which windows drove the current stage call, per StageFinder) + the transition matrix `Π` itself, which is directly interpretable and demos well ("here is exactly what the model believes happens after reconnaissance").
5. **Baselines to benchmark against (per PS requirement):** (a) the mandated logistic regression on flat flow features; (b) a plain BiLSTM over windowed flow-vectors with no graph and no explicit regime structure (Bontemps/Vinayakumar-style) — this isolates how much the graph structure specifically buys us; (c) optionally, PARD-SSM's single-regime Kalman filter ablation, to isolate how much the *explicit regime/stage structure* specifically buys us, independent of the graph.

This design is the only one of the six sub-areas' approaches that is (a) actually buildable from the PS's own named datasets without requiring host/EDR telemetry we don't have, (b) satisfies the explicit flow+packet dual-level feature requirement at the representation level rather than as an afterthought, (c) has each of its two halves (flow-graph GNN, regime-structured temporal head) independently validated in the literature with strong, recent, on-target benchmark numbers (X-CBA 98.7% F1; PARD-SSM 98.2% F1 + 8-minute predictive lead; StageFinder 96% macro-F1) we can credibly cite as precedent, and (d) is honest about where the genuine novelty is (§4's gap): nobody has combined the flow-graph-encoder family with the explicit switching/regime-transition family the way we're proposing, which is a legitimate, citable "beyond black-box classification" claim for the hackathon submission.
